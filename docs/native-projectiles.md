# 原生弹射物专项设计

本文件作为弹射物适配的专项笔记。顶层架构以 [通用原生施法框架](native-casting.md) 为准：下文 ProjectilePlan / ProjectileContinuation 的职责分别合并到 CastPlan / ContinuationPolicy，ProjectileAdapter 属于具体执行适配。持续法术的耗蓝、时间和接续策略以通用方案为准，不能套用单次弹射物规则。

0.2.0 已实现三种形态强化，在 Ars 完成速度／分裂处理后、实体入场前转换为真正的 Iron 弹射物。每个增幅累计 +1 级，转换时计算最终等级与伤害；不限制在原生最高等级内。后续穿透修饰、追踪与复合载荷仍未实现。实际行为与检查记录见 README。

## 接管时机

在施法方式生成实体之前完成选择、修饰映射和法术链拆分。避免先发射 Ars 实体再于飞行或命中时替换，否则需要移交运动、已命中目标、穿透预算、施法者和客户端同步，还可能产生两次碰撞／结算。

原生弹射物法术作为强化魔符改造已有 Ars 弹射物方式。例如：

`弹射物 → 火焰箭〔强化〕 → 加速 → 分裂 → 增幅 → 凋零〔效果〕`

计划统一读取该施法方式的修饰集合：火焰箭选择实体形态，加速／分裂作用于实体，增幅作用于原生载荷伤害。发射前创建 Iron 火焰箭实体，命中后执行原生命中行为，再恢复凋零所在的 Ars 后续法术链。仅对携带形态强化的编排接管，普通 Ars 弹射物继续走原逻辑。

## 建议职责

- `ProjectileAdapter`：按法术 ID 白名单选择实体工厂、允许的修饰和命中规则。能力不足时明确拒绝组合，不能假装支持。
- `ProjectilePlan`：分离施法方式修饰、原生载荷修饰和剩余 Ars 法术片段；冻结发射参数，决定蓝耗和权限检查。
- `ProjectileContinuation`：每枚实体自己的解析上下文、后续执行位置、命中去重与过期清理；分裂实体不共享可变解析游标。
- 命中接入：给本模组生成的原生实体附加标记与上下文，通过受标记约束的命中钩子接续 Ars。普通 Iron 怪物和玩家直接施放的弹射物保持原逻辑。
- 法术专用补充：原生火焰箭／冰锥的伤害可通过 `setDamage` 调整，但燃烧、冰冻、范围并不都由同一个伤害字段控制，需要对应适配，不能只设置伤害就宣称修饰全部支持。

## 必须明确的行为

1. 每次有效命中只结算一次原生载荷。后续 Ars 链跳过已由 Iron 结算的火焰箭效果及其修饰，避免再次伤害。钩子不能仅放在抽象基类 `onHitEntity` 返回处，因为子类可能尚未执行伤害。
2. 原生伤害保留 Iron 伤害来源和事件；不再走一次 Ars 对该载荷的强度换算。整条法术只在初始施放时由 Ars 扣蓝，后续解析不重新施放、不重复扣蓝。
3. Iron 与 Ars 的穿透含义不同：实体穿透不等于穿墙。初版可只支持伤害增幅、加减速和分裂；穿透、弹跳、追踪、范围分别添加能力声明后再开放。
4. 多载荷组合不能自动猜测形态。可先要求只有一个原生弹射物载荷，后面允许普通 Ars 效果；`火焰箭 → 冰锥` 等组合先判无效，后续再设计复合载荷或二次发射。
5. 未命中、反魔法移除、区块卸载和施法者失效时清理上下文；不为弹射物强制加载区块。需要跨卸载保留时再专门实现保存恢复。原生基类本身对区块卸载有不保存策略。
6. 逐类核实盾牌、命中事件取消和客户端同步。命中墙面是否继续 Ars 后续效果需要独立定义，不能直接当作命中生物。

已核对本机 Iron 3.16.3 的 `AbstractMagicProjectile`、`FireboltProjectile`，以及 Ars 5.13.1 的 `MethodProjectile`、`EntityProjectileSpell`、`SpellResolver`。Iron 有伤害、运动、穿透与追踪相关入口；Ars 的投射物保存解析器，在命中时继续解析。两者间缺少的是该实例携带的上下文及准确的命中接续，而不是生成实体的能力。
