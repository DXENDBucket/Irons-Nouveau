# 特殊形态中的闪电球存续

0.17.30 使用 Conflux 0.1.39 的显式接触策略。普通“弹射物”继续完全交给原生 Iron 弹体；Ars/NEG 特殊形态仍保留原载体负责轨迹与碰撞。

闪电球声明实体命中后继续存在。同一颗原始形态载体保留速度、年龄及形态状态，命中后继续推进；没有重新生成载体或重置轨迹。撞方块仍使用该形态原有规则，本批不额外给溅射弹添加闪电球的原生墙面反弹。

同一目标按原生规则至少间隔 10 个目标 tick 才再次尝试命中。无敌帧被清除也不会跳过该间隔。伤害失败仍按原生语义记录尝试间隔，但不收取未提交的触发费；缺少魔力时没有进行伤害尝试，不会消耗本次接触资格。命中前沿用原生的抑制击退。

## 范围与收费

- 一个真实接触展开的全部溅射目标共用一次提供者付款，各目标仍独立结算伤害与后续编排。
- 原本在生成时付费的形态仍在生成时收费，首个成功接触由这笔费用覆盖；以后接触重新支付一次。环绕等原本按触发收费的形态保留触发时付款。
- 后续 Ars/Iron 效果仍支付自己的费用，没有把它们并入闪电球的这次付款。
- 空蓝时拒绝新的作用，载体可以继续按形态运动；寿命结束或撞墙等条件照常清理。恢复魔力后，仍在存续的载体可以再成功触发。

Ars 控制的闪电球由形态寿命管理，原生自由飞行的 100 tick 截止不再提前删除该可见实体。普通原生闪电球仍使用它自己的截止规则。施法者离开、形态过期和会话关闭均清理载体与可见实体。

## 边界

接触策略由提供者声明，Core 不根据类名自动推断。当前为闪电球新增 `BALL_LIGHTNING` 载荷声明；其他 Iron 弹体、其他 Nouveau 附属和未托管原生法术均保持此前行为。新的同类载荷可复用 `ProjectilePayload.retainsEntityContacts` 和 `entityContactInterval`，具有有限穿透或独特命中状态的弹体仍需核对原生实现。

验证使用真正的 NEG/Ars 载体 tick 与实体碰撞，覆盖溅射后继续飞行、范围收费、再次命中、接触间隔、空蓝、环绕、寿命与普通路径回归。实际通过项与未验收项见本批构建记录；服务端验证不替代客户端外观验收。
